# User Guide

A screen-by-screen walkthrough of the Zonclave admin panel, for whoever is actually running it day to day. For how to install it, see [installation-guide.md](installation-guide.md). For the reasoning behind any of this, see [CLAUDE.md](../CLAUDE.md) - if that document and this one ever disagree, CLAUDE.md wins.

Everything here lives behind `/admin` and requires logging in first - none of it is public.

## 1. Dashboard

The home page after logging in. Stat cards for total, active, and disabled PPSK groups, each one clickable through to a pre-filtered list, plus a short registry-growth chart. This page loads data once, on open - there's no live auto-refreshing counter anywhere in the panel, so a stat card is only ever as fresh as your last page load or manual refresh.

## 2. PPSK Groups

The main inventory list - every Wi-Fi credential the system knows about, one row per group.

### Creating a PPSK

Click **New PPSK**. The fields:

- **Label** - any name you like. There's no required format - a suggestion list of existing labels appears as you type, purely as a convenience, never a requirement.
- **VLAN / tunnel** - a dropdown of the pre-provisioned VLANs. Picking a VLAN also fixes its subnet, WireGuard tunnel, and gateway - these three are always paired together and are never chosen separately.
- **RADIUS username** - auto-generated by default (`ppsk_group###`). Switch to "Enter manually" to set your own instead (3-64 characters: letters, numbers, underscores, hyphens).
- **Password** - auto-generated by default (a strong 24-character password). Switch to "Enter manually" to set a specific one instead (8-63 characters, matching the WPA2 personal PSK requirement).
- **Enabled** - on by default. A disabled group can't authenticate.

Whatever password is used - generated or manually entered - it's shown to you exactly once on the confirmation screen, with a copy button. Zonclave never shows it again after that; if it's lost, use Regenerate (below), not a support request.

### Editing a PPSK

Click **Edit** on any row. This opens a modal, not a separate page.

- **Label and VLAN** work the same as create.
- **RADIUS username** is directly editable here. Changing it takes effect immediately - **a device that's already connected using the old username will simply stop being able to reconnect**, with nothing in the panel flagging that this happened. Only change it if you mean to.
- **Regenerate password** is a toggle, off by default. Turning it on reveals the same auto-generate/manual choice as create. Leaving it off and saving only changes the label/VLAN/username - the existing password is left completely untouched.

### Enable / Disable

A single button per row that toggles based on current status. **Disabling asks for confirmation first**, since it immediately blocks that credential from authenticating again. Enabling is a single click with no confirmation, since it's reversible and non-destructive.

One thing this doesn't do: a device that's already connected keeps its session until it naturally disconnects. RADIUS is only consulted when a device first joins, not continuously - disabling stops the *next* connection attempt, not an existing one. If you need someone off the network right now, kick their device from the UniFi controller directly.

### Delete

Asks for confirmation, then removes the group and its underlying RADIUS credentials entirely. This does not touch the VLAN/WireGuard/firewall configuration on OPNsense - only the credential mapping is removed; the network-side setup for that VLAN stays exactly as it was.

## 3. Sessions

Shows who's actually connected right now, and who's connected recently - sourced from FreeRADIUS's own accounting records, not something Zonclave tracks itself.

Each row: which PPSK, the RADIUS username, the VLAN, the device's MAC address, the IP it was assigned on that VLAN, a "known egress IP" (see Tunnel Egress IPs below), when it connected, when it disconnected (blank if still connected), **why it disconnected**, how long the session lasted, and how much data it used.

The disconnect reason is whatever the access point itself reported (e.g. `User-Request` for a normal disconnect, `Idle-Timeout`, `Lost-Carrier`, `NAS-Reboot`) - Zonclave shows it as-is, it doesn't interpret or translate it. Blank means either the session is still open, or it went Stale (see Status just below) with no clean disconnect ever reported at all - the missing reason *is* the signal in that case.

**Status** is one of:

- **Connected** - actively seen recently, no disconnect recorded.
- **Stale** - no recorded disconnect, but also no activity in the last 15 minutes. This usually means the device just walked away, lost power, or dropped out of range without a clean disconnect - it isn't a bug, it's a real gap in how RADIUS accounting works (a clean "goodbye" packet isn't guaranteed).
- **Disconnected** - a clean disconnect was recorded.

Filter by VLAN, or toggle "currently connected only" to hide everything except live sessions.

This page shows nothing until FreeRADIUS accounting is actually turned on for this deployment - if it's empty and you expect sessions, that's the first thing to check, not a panel bug.

## 4. Tunnel Egress IPs

A small reference table, one row per provisioned VLAN, showing the WireGuard tunnel name and its last-confirmed public (residential) exit IP.

**This is not live.** There's no automated way today for the panel to ask a tunnel what public IP it's currently using - someone has to check it manually (e.g. `curl ifconfig.me` from a device on that VLAN, or the provider's own dashboard) and update it here via **Edit**. Every update records who confirmed it and when, so a stale-looking "last confirmed: 3 months ago" is a visible signal to go re-check it, not silently trusted.

The Sessions page (above) shows this same value next to each session as "known egress IP" - it's the same manually-maintained number in both places, not two different things.

## 5. VLANs

The list of VLANs a PPSK can be assigned to - this is what populates the VLAN dropdown on the PPSK create/edit form. Each row shows the VLAN ID alongside its automatically-derived subnet, WireGuard tunnel name, and gateway name, plus a live count of how many PPSKs currently use it.

- **Add** a new VLAN via the button at the top - just pick a VLAN ID (300 or above); everything else is derived automatically, the same fixed naming pattern every VLAN already follows.
- **Delete** removes a VLAN you're no longer using. **This is blocked if any PPSK - even a disabled one - still references that VLAN**, with an error naming exactly which PPSK(s) are in the way. Delete or reassign those first if you really want to remove it.
- The list doesn't need to stay a contiguous block - deleting one from the middle just leaves a gap, and a new one doesn't have to continue where the last left off.

This only manages which VLANs the *panel* knows about. It does not create, modify, or remove anything on OPNsense (the actual VLAN interface, WireGuard tunnel, or firewall rules) - that side is still built and torn down manually, per [opnsense-configuration.md](opnsense-configuration.md).

## 6. Admin Log

A read-only history: every admin login (success or failure), and every PPSK created, edited, enabled, disabled, deleted, or password-regenerated, plus every VLAN added or deleted. Filterable by action type. There is no way to edit or delete an entry - it's an audit trail, not a working list.

## 7. Profile

Change the admin account's own password. The email address is locked read-only, since there's only ever one admin account in Phase 1 and nothing to reconcile a changed email against.

## 8. Something looks wrong - where to check next

| Symptom | Likely first thing to check |
| --- | --- |
| A PPSK won't authenticate | Is it Enabled? Is the username/password actually what you think it is (Regenerate shows it once, but doesn't recover an old one)? |
| A device stopped connecting after an edit | Did the RADIUS username just get changed? The old one stops working immediately, with no notice to the device. |
| Sessions page is empty | FreeRADIUS accounting may not be turned on for this deployment yet - this is a one-time network-side setup step, not something the panel controls. |
| Egress IP looks wrong or very old | It's manually maintained (see Section 4) - go re-confirm it and update the record, rather than assuming the panel is measuring it live. |
| A disabled PPSK's device is still online | Expected - disabling blocks the *next* connection attempt, not an already-connected session. Kick it from UniFi if you need it off immediately. |
| Can't delete a VLAN | It's still assigned to a PPSK (see Section 5) - the error names which one. Delete or move that PPSK to a different VLAN first. |
| A VLAN I need isn't in the dropdown | Add it from the VLANs page (Section 5) - it's no longer a server-side/CLI step. |

For anything network-side (VLANs, tunnels, firewall rules), see [opnsense-configuration.md](opnsense-configuration.md) and, for this specific deployment, [Site Configuration](/docs/site-configuration) and [Troubleshooting](/docs/troubleshooting).
